# Краткий аудит репозитория tgbot

## Что в этом коде
- В репозитории фактически **2 Telegram-бота**:
  - `Gorilla_bot/bot.py` — универсальный ассистент с пользовательской памятью (raw/daily), ответами через OpenRouter, автопостингом из файла цитат и AI-автопостингом в канал.
  - `gonkaai/bot.py` — крипто-бот (BTC/ETH), автопостинг рыночной сводки по расписанию, чат-ассистент через Gonka API.
- Хранение памяти и состояния сделано в JSON/TXT-файлах в `data/`.

## Наблюдения по качеству и рискам
1. В `Gorilla_bot/config.py` лежат чувствительные ключи/токены в открытом виде.
2. В `Gorilla_bot` есть дублирующаяся логика памяти: часть функций внутри `bot.py`, часть в `memory/*.py`; есть следы незавершённой декомпозиции.
3. В асинхронных хендлерах используются синхронные вызовы OpenAI SDK, что может блокировать event loop под нагрузкой.
4. Есть широкие `except:` без типизации ошибок — сложно диагностировать проблемы.
5. План автопостинга в `Gorilla_bot` не сохраняется между рестартами (после перезапуска план дня формируется заново).
6. Почти нет защитных проверок конфигурации на старте (пустые env/невалидные значения времени и т.д.).

## Варианты оптимизации (без удаления функций)

### Вариант A — быстрый и безопасный (1–2 дня)
- Перенести секреты из кода в `.env` + добавить валидацию при старте.
- Добавить таймауты и ограничение ретраев для внешних API.
- Заменить `except:` на точечные исключения + структурированные логи.
- Сохранить все текущие сценарии (память, автопостинг, ассистенты) без изменения поведения.

### Вариант B — средний рефакторинг (3–5 дней)
- Выделить слои: `handlers/`, `services/`, `storage/`, `schedulers/`.
- Унифицировать память Gorilla (единый модуль вместо дублей).
- Вынести API-вызовы в сервисы, чтобы проще тестировать и ставить лимиты.
- Добавить блокировки/очередь для записи JSON, чтобы избежать гонок при параллельных событиях.

### Вариант C — масштабируемый (1–2 недели)
- Перейти с файловой памяти на SQLite/PostgreSQL (с миграциями) при сохранении всей текущей функциональности.
- Добавить кэш + circuit breaker для внешних API.
- Добавить метрики (latency, error rate, токены, автопостинг успех/ошибка) и healthcheck.
- Покрыть ключевые сценарии интеграционными тестами (ответы, память, расписание, публикации).

## Приоритетный порядок внедрения
1. Безопасность секретов и валидация конфигурации.
2. Неблокирующие вызовы/таймауты внешних API.
3. Рефакторинг памяти и структуры модулей.
4. Переход на БД и метрики.
